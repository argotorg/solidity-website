[Solidity v0.8.38](https://github.com/argotorg/solidity/releases/tag/v0.8.38) is out.

This release fixes a low-severity bug in the Yul optimizer.

The release also improves the performance of the `DataFlowAnalyzer`, which several Yul optimizer steps are built on.
As a result, compilation with the Yul optimizer enabled is faster.
In the IR pipeline, the function dispatcher now uses one fewer instruction to check that the calldata is long enough to hold a function selector.

The compiler now warns when `swapn`, `dupn` or `exchange` is used as an identifier in Yul or inline assembly.
These are the names of new opcodes that [EIP-8024](https://eips.ethereum.org/EIPS/eip-8024) introduces in the Amsterdam network upgrade.
The names are going to become reserved identifiers in Yul starting from the Amsterdam EVM version.
Like the existing `SWAP` and `DUP` opcodes, the new opcodes will not be available in Yul.
Solidity identifiers with these names are not affected.

## Important Bugfixes

### Yul Optimizer Knowledge Base Stale Bookkeeping

The Yul optimizer keeps track of the contents of memory and storage.
This lets it replace a load with a value it has already recorded.
It can also remove a store when it has recorded that the location already holds the value being stored.

The bug could occur when a Yul variable used to compute memory or storage addresses was reassigned.
One address might then be derived from the variable's old value and another from the new value.
The optimizer did not always notice that its knowledge about these two addresses had gone stale.
It could then treat them as distinct even when they pointed to the same location at runtime.
As a result, a load could be replaced with an outdated value, or a needed store could be removed.

Only code compiled with the Yul optimizer enabled is affected.
This is the case with `--optimize` or `--optimize-yul` (`settings.optimizer.enabled` or `settings.optimizer.details.yul` in Standard JSON).
With `--via-ir`, any code may be affected, including code without inline assembly.
Yul compiled directly with `--strict-assembly` may also be affected.
With the default evmasm pipeline, only two kinds of code may be affected.
These are Yul utility functions generated by the compiler and inline assembly blocks that do not refer to any Solidity variables or functions.
Whether a contract is affected depends on the intermediate code that the optimizer works on.
It cannot be reliably determined from the source code alone.
Versions 0.8.19 through 0.8.37 are affected.

We compiled verified contracts from the [Sourcify](https://sourcify.dev/) database with two development builds of the compiler, one with and one without the fix.
The fix did not change the bytecode of any of them.
This gives us confidence that the bug is very rare.
However, this result does not prove that no contract is affected.
The write-up linked below describes how to check deployed contracts.

The bug was reported by [Daniel Boye](https://github.com/DanielBoye) through the Ethereum Foundation's bug bounty program.
[Surya Prakash Akula](https://x.com/d4r3_d3v1l_) also reported the bug through the same program.
That report showed that the bug can be triggered from Solidity code without inline assembly.

## Full Changelog

### Important Bugfixes

* Yul Optimizer: Fix knowledge about storage/memory address relations going stale in the `DataFlowAnalyzer` after a variable is reassigned in Yul, which could cause `LoadResolver` to replace loads with outdated values and `EqualStoreEliminator` to remove needed stores.

### Compiler Features

* Commandline Interface: Remove the experimental `--yul-cfg-json` output.
* Commandline Interface: Selecting an ethdebug output no longer implicitly enables the `ethdebug` and `ast-id` components of `--debug-info`; without `ethdebug` in the selection the `--ethdebug-program` and `--ethdebug-program-runtime` outputs carry no semantic debug info.
* Standard JSON Interface: Remove the experimental `yulCFGJson` output.
* Standard JSON Interface: Selecting an ethdebug output no longer implicitly enables the `ethdebug` and `ast-id` components of `settings.debug.debugInfo`; without `ethdebug` in the selection the `evm.bytecode.ethdebug` and `evm.deployedBytecode.ethdebug` outputs carry no semantic debug info.
* Yul Analyzer: Warn about `swapn`, `dupn` and `exchange` being used as identifiers, since they are going to be reserved identifiers starting from the Amsterdam EVM version.
* Yul IR Code Generation: Use `gt(calldatasize(), 3)` instead of `iszero(lt(calldatasize(), 4))` in the external dispatch routine of IR codegen, saving one instruction per external call.
* Yul Optimizer: Improve performance of `DataFlowAnalyzer` using flat hash containers.

### Bugfixes

* EVM Assembly Import: Fix target EVM version being ignored when assembling imported experimental EVM assembly JSON.
* Parser: Fix inverted version pragma range comparison for components in the range [2\*\*31, 2\*\*32).
* Yul Parser: Fix `@use-src` source indices that are not decimal numbers being silently truncated instead of rejected.

### Build System

* Switch from C++20 to C++23 as the target standard.
* Update emscripten to version 3.1.54.
* Update minimum version requirement of Clang to 19.1.1.

### Solc-Js

* The wrapper now requires at least nodejs v16.

## How to Install/Upgrade?

To upgrade to the new version of the Solidity Compiler, please follow the [installation instructions](https://docs.soliditylang.org/en/v0.8.38/installing-solidity.html) available in our documentation.
You can download the release from GitHub: [v0.8.38](https://github.com/argotorg/solidity/releases/tag/v0.8.38).

If you want to build from the source code, do not use the source archives generated automatically by GitHub.
Instead, use the [`solidity_0.8.38.tar.gz` source tarball](https://github.com/argotorg/solidity/releases/download/v0.8.38/solidity_0.8.38.tar.gz) or check out the `v0.8.38` tag via git.

And last but not least, we would like to give a big thank you to all the contributors who helped make this release possible!
